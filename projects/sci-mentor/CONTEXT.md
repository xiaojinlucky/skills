## 近期关键决定

1. 只做功能蒸馏，不冒充 BioAdvance 本人，不做强人物扮演。
2. 内容层、任务层和证据层是主轴，来源类型只用于追溯、去重和质量控制。
3. 使用一个主 Skill、按任务调用的方法单元、严格来源锚点和轻量只读检索，不引入多 Agent 运行框架、向量数据库或知识图谱。
4. 任务 workflow 和创作者方法单元分层。24 个科研环节不等于必须有 24 条创作者方法。
5. 创作者方法与项目科学守门规则分层记录，守门规则没有一手依据时保持待审，不能反向归因。
6. 单一阶段窄任务不自动扩展到相邻证据评级或补实验设计。方法单元的执行步骤、完成条件和停止条件必须真实落到答案中。
7. 原始材料命中只说明材料中出现过某观点，不等于方法已通过蒸馏，也不能替代当前论文、原始数据和一手科学证据。
8. 终稿必须符合中文生信与科研社区表达习惯，删除无效防御性写作，但保留真实证据边界。
9. 当前版本已安装并全局同步用于真实任务试用，但方法单元仍保持 `candidate`；安装成功不等于正式方法学验收。
10. 三个入口服从同一条递进主线。读文献是入口，科研思维训练是深化，自己的课题设计和推进是最终落点。
11. 基础版是读文献部分的核心方法来源。保留问题驱动、整体框架预览、Figure 骨架、逐步逻辑解释、批判性思考和课题迁移；不照搬营销语气、期刊分数、固定机制层数和过强因果说法。
12. 普通回答不暴露模式、阶段、方法编号、锚点和候选状态等维护术语，优先使用中文科研社区自然、准确且容易理解的表达。
13. GitHub 只保存可审查的项目快照，不上传原始课程、知识星球数据库、音视频、完整本地转写、虚拟环境、scratch 或 Codex memory 原文件。网页版 GPT 的规划必须由本地 Codex 结合实际 Skills、memory 和运行环境重新落地。
