# Lessons

## 2026-07-15

- 不得把原始资料提取、建立索引、少量代表性证据卡和完整语料蒸馏混为一谈。
- BioAdvance 项目应先覆盖并准确分类 B 站、公众号、知识星球、基础班、专业版等各类材料，再进入方法提炼和 Skill 定稿。
- 每条提炼规则必须保留来源类别、稳定来源定位、适用任务、证据功能和人工审核状态，支持按任务渐进调用。
- 语料层尽可能全面，工具层保持轻量。优先使用 Markdown、JSONL、SQLite FTS 与少量确定性脚本，不先引入向量数据库或复杂 Agent 框架。
- 语料覆盖摘要和候选方法模型必须先向用户展示并确认，未经确认的内部状态不得表述为用户已接受或正式完成。
- 来源类型只作为追溯元数据，不是语料知识组织的主分类轴。主分类应服务文献解读和科研思维培养，优先采用内容层、任务层和证据层。
- 内容与任务分类应对应真实科研环节，例如背景问诊、文献调研、科学问题形成、研究缺口判断、假设构建、创新性与可行性评估、Aim 与 Figure 设计、结果解释和证据闭环。
- `F:\科研大师兄\my skills\meta-sci-init\meta-sci-init` 是开题任务结构的重要参照。其阶段流程和主线映射可以借鉴，但具体方法规则仍需回到 BioAdvance 原始材料核验，不能把参照 Skill 当作一手证据。

## 2026-07-16

- 本项目是面向文献解读与科研思维训练的主题型 Skill，不做 BioAdvance 人格扮演，也不把口头禅或表面文风当成核心产物。
- 从同事 Skill 只借鉴有证据的工作方法提取、增量补充、重复信息忽略、矛盾显式呈现和用户纠错补丁，不引入人格层、MBTI 或职场角色扮演。
- 从女娲 Skill 借鉴本地材料优先、跨场景复现、生成与预测能力、非通用性三重筛选，保留矛盾、反模式和诚实边界；不照搬人物身份卡、时间线和全网人格调研。
- 从仓颉 Skill 借鉴全局理解、框架/原则/案例/反例/术语五视角提取，以及来源、解释、触发、执行、边界组成的可调用知识单元；每个单元还需有不触发条件和相邻任务混淆测试。
- 保持一个主 Skill 加任务感知证据库，不把每条方法拆成独立 Skill，不引入重型多 Agent 运行框架。原始材料可全面保留，运行时只按当前科研环节调用最相关的少量知识单元。
- 入口级流程与原子方法单元必须分层。一个原子单元只完成一个主要科研决策动作，覆盖多个阶段的内容只能作为 workflow 编排，不能用一次测试替代各动作的独立验收。
- 创作者材料提炼出的原始方法与项目为科研严谨性增加的守门规则必须分开记录。不能把项目纠偏反向归因给 BioAdvance，也不能用创作者材料代替当前科学方法学证据。
- 三重筛选必须保留跨科研语境证据、生成测试和操作性非平庸对照，不能用来源数量或一个 `pass` 标签冒充验证。
- Skill 的验收不仅检查任务做对，还要检查是否显性教会用户当前判断、决定性证据、可复用问题和会改变判断的新证据。

## 2026-07-17

- `sci-mentor` 的固定定位是三层递进。表层是解读文献，深层是培养科研思维，最终目标是帮助用户设计并推进自己的课题。三个层次不能被拆成互不相干的功能。
- 读文献模式必须重点参考 `做科研的大师兄-科研自救指南，基础版.pdf` 的内容组织和讲解顺序。该 PDF 未完成文字识别和核对前，不能声称已经吸收其方法。
- 参考基础版材料时，应保留问题驱动、先讲判断、分步解释、回到科研能力和课题迁移的结构；不照搬营销标题、夸张语气或口头禅。
- 内部的方法编号、阶段状态、来源账本和测试术语只用于维护和核验，不应增加用户的理解负担。对外表达首先保证中文生信和科研语境中的准确、自然和易懂。
- `sci-mentor` 不进入既有的 `ai-agent-configs` 或其他项目仓库。GitHub 交接应使用独立的新 Private 仓库 `skills`，在其中以独立目录保存本项目，避免与历史配置和其他 Skill 改动混合。
- 网页版总控工单只能作为验收目标，凡涉及本机 Skill、memory、私有语料、Python 和远端节点的判断，都必须回到实际环境重新核对并按现实调整。
- 真实任务验收应隔离生成与评价，并同时检查科学内容和中文科研表达。确定性脚本只能拦截字符、套话和内部术语，不能用固定关键词命中代替语义判断，也不能逼终稿套用机械句式。

## 2026-07-20

- 对外发布资料时，快捷方式只能用于定位原文件，不能把 `.lnk` 当作资料上传。必须核对快捷方式指向的真实文件存在，并以真实文件为来源。
- `Resources` 仓库中的 BioAdvance 资料统一收进 `做科研的大师兄/`。该目录下只按 B站文字稿、知识星球、基础版和专业版分为四类。
- 超过 GitHub 单文件限制的原文件必须先分卷。分卷文件继续放入所属资料目录下的专用子文件夹，不能散落在仓库根目录或四类资料的第一层。


## 2026-08-28

- README 视觉资产必须经过成品级可视化验收，不能以 SVG 语法正确或代码生成成功代替视觉通过。
- Hero 在 GitHub 桌面宽度与窄屏缩放下都必须保持安全边距、清晰对比和无重叠；重要信息留在 Markdown，图内避免密集小字。
- 制作与审查分阶段进行。审查只按最终渲染结果检查重叠、裁切、层级、头像、链接、alt 文本和实际 Markdown 呈现，发现问题必须修复后重审。
