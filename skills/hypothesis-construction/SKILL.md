# 科学假设构建

## 共享内核

进入本 Skill 前，通过当前宿主的 `research-master` suite manifest 或等价资源解析器始终读取：

- `shared/research-core.md`
- `shared/expression-core.md`

仅当任务要形成正式验证、执行方案、独立验证或更新 `validity_gate` 时，按需读取 `shared/execution-and-validity.md`。

这里使用逻辑资源名，不依赖用户目录或宿主私有绝对路径。资源无法解析时明确说明并按最小降级继续，不猜测共享规则。

本文件只负责从项目内证据形成可证伪假设。

## 独立职责

- 把观察、候选关系和解释性故事区分开。
- 明确假设的对象、方向、背景、时间窗和预期读出。
- 给出至少一个合理竞争解释。
- 说明什么结果支持、削弱或推翻假设。
- 选择下一项最高信息增益的验证，不提前填满整条机制链。
- 随新证据局部更新假设，保留未被推翻的部分。

## 进入与退出

**进入条件**：至少有一个来自当前项目的可信观察、异常、候选或明确临床现象。

**不要进入**：

- 只有宽方向，没有项目内信号：先用 topic-convergence 或 meta-sci-init。
- 需要从数据寻找具体机制候选：用 mechanism-design。
- 已有明确因果 claim，要设计干预：用 causality-rescue。
- 只需要复现论文：按 EXPLICIT_REPLICATION_TARGET 处理，不冒充新假设。

**退出条件**：形成一个可证伪主假设、主要竞争解释、证据边界和下一项判别性工作。

## 假设不是故事

一个科学假设至少包含：

1. **观察起点**：当前项目真实看见了什么；
2. **解释关系**：哪些对象可能怎样影响另一个对象或表型；
3. **适用边界**：在哪类样本、细胞、阶段、条件或时间窗成立；
4. **可观测预测**：如果关系成立，应看到什么；
5. **反证条件**：什么结果会削弱或推翻它；
6. **竞争解释**：还有什么同样能解释当前观察。

A→B→C→D 可以帮助用户画出一个线性候选关系，但网络、反馈、细胞间互作、动态状态、临床队列和纯计算问题不应被强塞进这条线。符号服务思考，不拥有事实地位。

## Discovery-first 顺序

默认顺序：

当前数据、异常或现象
→ 无偏描述与技术核查
→ 形成候选关系
→ 写出最小假设和竞争解释
→ 用文献划定已知边界、矛盾和 GAP
→ 选择判别性验证
→ 根据结果更新假设

不得把从论文挑出的基因、配体受体、通路、program 或机制轴直接当作已成立假设，再回自己的数据寻找支持。文献可以先提出待验证问题或暂定工作假设；进入本 Skill 的正式假设构建仍需当前项目的可信观察、异常、候选或明确临床现象，文献空白不能单独证明关系存在；反过来，缺少高水平先例也不能自动淘汰项目内可信信号。

## 执行流程

### 1. 建立证据清单

分别列出：

- 已观察事实；
- 质量或技术边界；
- 当前推断；
- 尚未验证的机制语言；
- 与文献一致、部分一致、相反或未报道之处。

### 2. 写最小主假设

优先只包含当前证据足以支持的对象和方向，例如：

在背景 C 中，A 的变化可能通过过程 B 改变表型 Y。

不确定的中间节点先保留为空，不为完整感预填。表型、机制和功能终点的界线由实际 claim 决定，不按字母位置机械定义。

### 3. 写竞争解释

至少考虑最可能改变主线的一到两个替代解释，例如：

- A 和 Y 由共同上游驱动；
- 信号来自细胞组成或批次变化；
- 方向相反，Y 反过来改变 A；
- 关系只在特定阶段或背景成立；
- B 是伴随标志而非中介；
- 网络有并行或冗余路径。

不要罗列所有理论可能性。

### 4. 生成判别预测

对主假设与竞争解释分别写：

- 什么观察会更支持它；
- 什么观察会削弱它；
- 哪个结果能真正区分二者；
- 结果如何改变下一步。

### 5. 选择最低充分验证

优先选择同时满足以下条件的工作：

- 能解决一个仍然活着的不确定性；
- 不同结果会改变路线或 claim；
- 在当前资源和阶段可完成；
- 不要求先完成整套最终验收。

验证可以是分层分析、独立数据、时间顺序、正交测量、扰动、定位、互作、预实验或因果实验。具体方法交给相应 Skill。

### 6. 更新而不是重写全部

新结果只推翻一个边或限定一个背景时，局部修改假设；不要因为一处 finding 让全部正确观察失效。自己的可靠结果若与论文相反，先查技术和背景，仍成立时把冲突作为候选 GAP。

## 输出合同

1. 当前项目内证据与边界；
2. 一句话主假设；
3. 适用背景和当前 claim 强度；
4. 主要竞争解释；
5. 能区分解释的预测；
6. 下一项最低充分验证；
7. 支持、部分支持、相反和无效结果各自如何改变假设；
8. 明确仍不能说什么。

## 常见失败

- 先写完整故事再找数据；
- 把文献已有答案换一个背景后当成新假设；
- 把相关性写成因果；
- 强迫所有课题使用线性 A-B-C-D；
- 认为中间节点越多、rescue 越多就一定更高级；
- 表型或核心观察不稳定时提前堆机制；
- 只有一个预期结果，没有竞争解释和反证条件；
- 一次局部失败就推翻所有已验证部分。
