# 中文生信社区推文

## 共享内核

每个任务只读取一次当前宿主 `.codex-shared/suites/research-master/shared/research-core.md`；需要生成用户可见中文科研内容时读取 `expression-core.md`。科研事实、创新隔离墙、证据强度和共同表达只以这些 shared canonical 与当前项目证据为准，本 Skill 不再复制一套科研方法论。

**进入条件**：用户要把已有材料写成中文生信小红书推文、平台长文或评论区短回复，而且任务不是需要可运行代码、完整图片与系列工程的 BioTutor 教程。

**唯一负责的决定**：怎样把已经成立的内容转成适合中文生信社区的标题、结构、术语、节奏、配图和可直接发布文本。

**退出条件**：事实范围、受众和输出形态明确，正文与必要图片引用已经完成平台适配并通过相关检查。

**交接对象**：

- 需要补论文事实或重建发现过程 → `literature-deep-reading`；
- 需要完整可运行官方教程 → `bio-tutorial-writer`；
- 需要写或审科研论文 → `sci-writing-and-revision`；
- 需要生信代码与科研图 → `bio-code-style` / `omics-coding`；
- 一般中文长文而非生信平台适配 → `human-writing`。

## 先确定这篇内容在解决什么

从现有上下文恢复：

- 面向谁；
- 读完后要理解、判断或完成什么；
- 哪些事实已经有证据；
- 是原理解释、方法选择、论文解读、结果判断、教程片段还是评论区回复；
- 用户给定的长度、平台和配图要求。

已有信息足够时直接写，不再问标题、篇数、段落数或是否开始。缺少会改变科学含义的材料时才问一个关键问题。

不要把“小红书”理解为必须焦虑营销、夸张标题或每段一句话。平台适配服务理解与行动，不改变事实强度。

## 科学内容边界

### 事实先于文风

- 软件版本、函数、参数、年份、期刊、benchmark 结论和论文主张在依赖前核实；
- 当前课题的候选、机制和故事只能由当前课题证据产生；
- 文献可以提供方法、发现路径和已知边界，不能默认预填本项目答案；
- 没有高水平论文先例不能自动否定来自当前数据的新信号；
- 观察、推断、假设和验证事实使用不同强度的表达。

### 不继承固定科研答案

`A-B-C-D`、rescue、固定 Figure 数、固定样本数、固定通路或固定候选都只是可能的工具，不是平台文章的通用科学真理。是否采用由当前问题、claim 和证据决定。

用户要求讲“师兄的方法”时先核对其真实原文或用户已确认材料。只迁移能被来源支持、且对当前主题有用的观点；不凭记忆制造数字、金句和绝对判断。

## 中文生信社区表达

### 术语

- 软件包、函数、基因、指标和期刊名保留领域通用英文；
- 陌生术语首次出现时紧跟一句最短中文解释；
- 能用自然中文说明的概念不堆英文；
- 同一对象尽量使用具体名称，不连续用“它/它们”让读者猜；
- 使用社区真实常用词，例如“批次效应”“过滤掉”“分辨率”，不自造“批次假象”“零信息”等术语。

### 语气

写成有实操经验的人平静解释：

- 先给判断或问题，再给证据和做法；
- 不用“综上所述、值得注意的是、不难发现、让我们看看”等模板套话；
- 不用“颠覆、炸裂、重磅、课题就废了”等夸张或焦虑营销；
- 不用无信息免责声明包围每个判断；
- 真实限制只在对应位置写一次，并说明来源、范围或证据强度；
- “大师兄”只在确实引用用户本人已确认的观点时出现，不作为机械叙述者。

### 标题

标题必须让读者知道具体主题和能得到什么。可以是：

- 真实问题：`FindMarkers 和 pseudobulk 到底怎么选`；
- 具体承诺：`工具结果变成课题结论，要经过三次判断`；
- 现象与判断：`UMAP 上的一小群细胞，先区分稀有亚群和批次效应`。

不固定疑问句，不为钩子夸大后果，不塞与正文无关的数字。

### 结构

结构由内容决定：

1. 用真实场景或核心判断开头；
2. 解释为什么会出现这个问题；
3. 给出最少充分的判断方法、步骤或证据；
4. 用一个具体例子帮助迁移；
5. 在真正需要时写边界与下一行动。

小问题可以很短，复杂方法可以使用二三级标题。不要固定 3000–5000 字、6–8 个标题或每段 80–100 字；以读者能一次看懂且没有重复为停止条件。

### 格式

- 中文正文使用自然中文标点；
- Markdown 层级最多三级；
- 加粗只用于关键定义和结论，不凑数量；
- 代码、函数、路径和命令使用代码格式；
- 用户要求可直接复制时，只交付成稿，不在正文前后加模型旁白；
- 评论区回复服从用户字数与语气，直接回答，不套长文结构。

## 配图

配图只有在降低理解成本时使用：

- 解读具体论文 Figure 时，使用用户提供或从合法来源取得的真实原图，并给出对应说明；
- 解释抽象结构或关系时，可以生成简洁示意图；
- 数据图必须来自真实数据和可追溯代码；
- 纯流程或短判断文字已经足够时不为“完整”硬配图。

不得伪造论文截图、实验图或数据结果。下载失败时报告真实限制；不要用不相干图片填位。图片路径、图注和正文引用在交付前逐一核对。

## 执行流程

1. 读取用户材料、项目规则和 Research shared canonical；
2. 只补会影响当前文章的事实缺口；
3. 形成核心判断和证据顺序；
4. 写出最短完整初稿；
5. 检查科学含义、术语解释、标题承诺、段落重复和图片对应；
6. 只修真实问题，验证已足够时停止；
7. 直接交付可复制成稿和必要来源/图片路径。

普通推文不自动建立系列规划、来源 ledger、多 Agent Review 或固定质量评分。正式发表前如果存在会改变事实正确性的活未知，再进行相匹配的核验。

## 自检

- 当前事实是否来自项目证据或已核实来源；
- 是否把别人的生物学结论误当成本项目候选；
- 是否把师兄历史观点写成跨项目硬规则；
- 标题承诺是否与正文一致；
- 陌生术语是否首次解释；
- 是否存在 AI 套话、焦虑营销、无信息防御或重复段落；
- 长度、标题数、加粗数和配图数是否由内容决定；
- 评论区短回复是否真的保持简短；
- 图片和来源是否真实可追溯；
- 最终文本是否可以直接使用。
