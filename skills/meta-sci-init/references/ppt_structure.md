# 开题报告 PPT 生成说明

第 ⑦ 阶段是**默认关闭的按需阶段**。只有用户明确要求生成、制作、导出或整理开题答辩 PPT 时才读取并执行本文件。完成开题报告本身不能自动触发 PPT，也不能提前检查、安装或调用 PPT 生成能力。

## 工作方式
**优先级：官方 `pptx` 技能（路径 A） > 内置脚本（路径 B）。** 完整流程见 SKILL.md ⑦。

- **路径 A（首选）**：做 PPT 前先确认官方 `pptx` 技能是否可用；不可用则向用户列出
  「要装的技能(pptx)/来源(github.com/anthropics/skills)/安装位置(~/.claude/skills/pptx/)」并
  **征得明确许可**，同意后自动 `git clone` 安装，再 Read 其 `SKILL.md` 并遵循它生成
  `开题报告PPT.pptx`。内容组织仍按下面的映射与排版原则。

- **路径 B（降级，用户拒绝或安装失败时）**：
  1. AI 把已确定的开题方案整理成 `content.json`（结构见下），写到用户工作目录。
  2. 运行 `python scripts/build_pptx.py content.json 开题报告PPT.pptx`。
     - 已安装 `python-pptx` → 直接生成 `.pptx`（16:9，封面+目录+正文+致谢，含演讲者备注）。
     - 未安装 → 自动降级生成 Marp 幻灯 `.md`，并提示 `pip install python-pptx` 或用
       `npx @marp-team/marp-cli xxx.md --pptx` 渲染。

## content.json 结构
```jsonc
{
  "meta": {
    "title": "论文题目",        // 必填
    "subtitle": "副标题",       // 可选
    "author": "汇报人",
    "advisor": "指导教师",
    "institution": "单位",
    "date": "日期"
  },
  "thanks": "恳请各位专家批评指正！",   // 结尾致谢页，可选
  "slides": [
    {
      "title": "幻灯标题",
      "bullets": [
        "一级要点（字符串）",
        ["二级要点", 1],           // [文本, 层级] 层级0-4，0为一级
        {"text": "也可用对象写法", "level": 1}
      ],
      "notes": "演讲者备注，写进 PPT 备注栏，可选"
    }
  ]
}
```

## 汇总方案 → 幻灯的建议映射
把开题报告压缩成 **7-9 页正文**（加封面/目录/致谢），不要照搬全文。

| 幻灯页 | 来自开题报告的哪部分 | 要点密度 |
|---|---|---|
| 研究背景与意义 | 第1节 | 3-4 条 |
| 国内外研究现状 | 第2节 | 4 条，突出核心缺口 |
| 研究问题与目标 | 第3节 | 核心问题 + 2-4 子问题 |
| 研究内容与技术路线 | 第4、6节 | 内容分块 + 一条技术路线 |
| 创新点 | 第5节 | 1-3 条，每条有文献或前期依据 |
| 可行性分析 | 第7节 | 理论/技术/条件/关键风险 |
| 研究计划与预期成果 | 第8、9节 | 阶段表 + 成果 |

## 排版与表达原则
- **每页 ≤ 6 条**，每条 ≤ 1 行，用短语不用整句。
- 一页只传达一个主要信息。标题直接说明本页处理的问题或有证据支持的判断。
- 用**层级**表达从属关系，不要在一条里堆多个点。
- 关键术语、研究对象和数字前置。演讲的完整话术放 `notes`，不放正文。
- 首次出现的陌生术语、缩写和统计指标在 `notes` 中用一句普通中文解释。
- 每张图或技术路线都要让听众知道应该看哪里、它支持什么判断、与课题主线有什么关系。
- 封面标题使用论文题目，结尾用致谢页收束。
- 页面先呈现核心判断，再呈现支撑证据。必要局限放在对应页面末端或演讲者备注中。
- 生成完成后执行一轮事实边界、中文科研表达、防御性写作和可理解性自查。

## 触发时机

**唯一触发条件是用户明确要求 PPT。** 在此基础上，④ 已定题且⑥ 报告主体成形时生成效果最好。若用户在报告未完全定稿时已经明确要求 PPT，可用当前已确定内容生成，未定处在 bullets 里标「【待补充】」。如果用户没有明确要求，任何阶段都不生成 PPT。
