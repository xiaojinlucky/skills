# Meta Research Hub

这是跨阶段科研问题的总入口。它帮助你把目标、证据、未决问题和资源限制放到同一张图里，再决定先处理哪一个判断。

## 什么时候使用

- 课题方向还很宽，不知道从哪里收敛。
- 文献读了不少，却还没有找到可以核验的 GAP。
- 不同分析或实验结果互相矛盾，需要判断先复核什么。
- 假设、机制、预实验、论文或开题材料之间需要安排顺序。
- 资源有限，需要决定继续、收缩、转向或停止。
- 想比较多篇论文实际怎么做，或把一篇论文的图、正文、图注和 Methods 串成主线。
- 不同方法名看起来不同，但怀疑它们实际承担的是相近功能，或想把文献整理成方向级工作地图。

问题已经明确且只属于一个专业阶段时，直接使用对应的核心 Skill，不必先经过这个入口。

## 工作方式

1. 先确认研究目标、已有证据、当前卡点和资源限制。
2. 判断当前最需要解决的未决问题，以及它会影响哪一项研究决定。
3. 只选择能直接处理这些问题的核心 Skill，按依赖关系安排顺序。
4. 把观察、推断、假设和已经验证的事实分开，避免把文献结论写成当前项目的答案。
5. 优先安排会改变主线或下一步的工作，给每项工作写清完成信号和停止条件。
6. 汇总专业判断，形成下一项行动；信息不足时说明缺口，不猜测。

## 科研判断原则

1. 从当前项目的观察、异常和证据出发。文献用于学习问题如何提出、证据如何推进，以及划定已知边界。
2. 科学问题决定方法。方法需要服务当前 claim、论文主线和实际资源，方法数量本身不代表研究质量。
3. 探索阶段可以调整合适的分析、参数、分组或可视化来寻找信号。关键路径要留有记录，确认性结论要做相称复核。
4. 结论强度服从证据。保留竞争解释和决定性反证，不把相关性写成因果。
5. 有限预算优先用于能改变判断的工作。证据已经足够支撑当前目标时，明确可以停在哪里。

## 输出

回答应至少包括当前判断、关键依据、下一项行动和停止或转向条件。用户只给一句卡点时，先基于现有信息给出“当前判断—关键缺口—最小下一步—停止条件”，缺失信息标为未知，不要求用户先填完整表格。需要多个 Skill 时，说明每个 Skill 要解决的问题和建议顺序。

## 文献综合：横向—纵向—方向图

当问题是“某个任务通常怎么做、该选什么方法”“多篇论文实际做法有什么共同点”“一篇论文到底怎样从观察走到结论”，或“这些文献能不能形成一个可行动的研究方向”时，按最终判断路由：

1. **方法怎么做/怎么选**：先由 `literature-mining` 区分专用工具轨和 DIY 基础操作轨，优先核对目标场景应用论文的实际做法，再按需要进入横向或纵向分析。
2. **多篇论文比较共同功能**：`literature-mining` 横向比较 → 对会改变判断的关键论文做纵向核对。
3. **看懂一篇论文**：`literature-mining` 先纵向重建 → 只有需要判断代表性或迁移性时再横向。
4. **反推隐性方法**：从结果终点倒推输入和最小操作 → 回正文、图注、Methods、补充材料或代码核实。
5. **形成方向级地图**：横向 → 纵向 → 合成带来源和证据状态的工作地图 → 必要时交给 `topic-convergence`。

地图中的关系应写成观察、使用、支持、提示或待验证，不因叙事顺序或跨论文共同出现而自动变成因果；文献地图只能提供问题空间和方法线索，不能替代当前项目证据。逐篇核对前只能写“暂定功能相近/推断待核实”，完成输入、操作、筛选规则、输出语义和情境核对后，才可写“已核验的功能等价”。

不固定论文数量、ABCD/Aim 链或图形格式；以是否改变当前判断和下一步为停止依据。方法推荐不以“专用工具清单”作为终点：需要时同时说明应用论文实际采用的基础操作、代表性实例、收敛与分歧，以及它们对当前判断的影响。输出至少说清：横向共性与差异、纵向主线、哪些是明确事实/功能等价/待核实推断，以及“这份产出改变什么、下一步做什么、什么信号下继续或停止”。

它不代替具体实验、数据分析、写作执行、伦理审批、临床诊疗、正式统计审查或当前官方制度核验。
