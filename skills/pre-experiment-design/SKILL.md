# 预实验设计

## 共享内核

进入本 Skill 前，按当前宿主提供的共享科研规则读取：

- `shared/research-core.md`
- `shared/execution-and-validity.md`
- `shared/expression-core.md`

这里使用逻辑资源名，不依赖用户目录或宿主私有绝对路径。资源无法解析时明确说明并按最小降级继续，不猜测共享规则。

本文件只负责预实验的决策设计。

## 独立职责

- 明确预实验要消除的一个或少数关键未知。
- 选择最低充分的模型、分组、样本和读出。
- 先验证技术可行性、核心观察或关键因果边中当前最脆弱的一项。
- 预先定义成功、部分成功、失败和实验无效分别怎样改变下一步。
- 保护不可替代样本和记录材料去向。
- 让前期证据服务真实课题或申请要求，不为完成度数字做实验。

## 进入条件

至少需要：

- 来自当前项目的候选、异常或明确问题；
- 预实验结果要支持的决策；
- 可用模型、样本、技术、时间和预算；
- 当前最可能让项目失败的一个不确定性。

如果候选仍主要来自论文而非项目证据，先回到 topic-convergence 或 hypothesis-construction。需要详细机制候选时用 mechanism-design；需要因果或 rescue 设计时用 causality-rescue。

若任务明确是复现或外部验证论文中的关系，可以据此设计最低充分预实验，但需明确标注为 replication / validation，并把成功标准限定为当前模型中的可重复性、边界和方法可行性；论文关系不会自动变成新的发现或机制 claim。

## 预实验的目的

预实验不是缩小版“把整篇论文先做一遍”，而是用最低成本回答：

- 观察是否稳定存在？
- 模型或测量是否可用？
- 干预是否真正改变目标？
- 关键表型是否朝可解释方向变化？
- 某个竞争解释是否足以推翻当前路线？
- 是否值得投入正式实验、组学或更昂贵模型？

如果实验结果不会改变任何决定，就不把它加入预实验。

## 执行流程

### 1. 写出决策问题

使用一句话：

如果结果为 X，我们继续 Y；如果为 Z，我们停止、换模型或降低 claim。

一次预实验优先解决一个关键未知。多个未知彼此独立时拆开，不把所有方法塞入同一批样本。

### 2. 选择最低充分模型与干预

根据问题选择：

- 表达或定位的正交确认；
- 技术可行性和动态范围；
- loss-of-function 或 gain-of-function；
- 时间、剂量或阶段窗口；
- 一个能区分主要替代解释的对照；
- 必要时的回补或 rescue；
- 小规模 discovery assay 或组学试运行。

rescue 只在能区分脱靶、中介关系或关键因果 claim 时使用，不是所有预实验的必需项。

### 3. 设计分组、重复与样本量

先确定：

- 实验单位和独立重复是什么；
- 主要比较和主要终点；
- 预期效应、变异与最小有意义差异；
- 技术失败率、批次和配对结构；
- 是否需要 power analysis 或精度目标；
- 预算与不可替代样本边界。

bulk、单细胞、质谱、宏基因组和动物实验不能共享一个固定样本数。经验值只能用于初始估算，最终方案应由设计、变异、平台和目标决定。若用户没有提供实验单位、主要终点、预期效应、变异或本轮决策目标，通用回答默认只说明样本量的决定依据，不给出统一的 n、3、5 或固定重复次数；只有用户明确要求粗略可行性估计时，才可给出带假设的临时范围，并说明它不是正式样本量、通用方案或停止标准。此时仍应把范围与本轮决策绑定，说明什么结果支持继续、优化或扩大，什么结果支持停止、换模型或降低 claim；关键信息不足时，把这些分支标为待填判据，不让数字本身代替决策。

### 4. 设置对照与质量观察

至少覆盖与当前问题相关的：

- 阴性、阳性或基线对照；
- 干预是否生效；
- 测量是否处于可靠范围；
- 批次、毒性、细胞组成或一般损伤；
- 数据排除标准和失败判据。

不要为了模板完整添加不会改变解释的对照。

### 5. 预先定义结果分支

- 先标记本次结果属于探索性 pilot 还是确认性验证。探索性 pilot 可以筛选或削弱候选，但单凭小样本、事后挑选或同一数据集的筛选结果，不能升级为确认性机制或因果结论；若要升级，说明预先确定的主要终点和相称的独立确认依据。
- **支持**：最多能把 claim 提升到哪一层，下一项正式工作是什么；
- **部分支持**：保留哪些观察，放弃哪些机制语言；
- **相反**：检查技术和背景后，是否提示方向反转或新 GAP；
- **无差异**：区分干预无效、功效不足和真实无效；
- **实验失效**：修复方法，不把失败冒充生物学结论。

### 6. 管理样本与派生产物

在采集不可替代样本前，按当前组织、测量目标、保存条件、伦理和平台 SOP 决定分装和保存。不要机械规定所有组织“三份保存”；也不要在目标不明时耗尽样本。

明确：

- 原始样本与不可替代材料；
- 当前检测需要的分装；
- 剩余材料的保存条件和期限；
- 原始数据、质控、分析产物和临时文件的生命周期。

### 7. 决定是否进入正式实验

只有预实验已经解决当前关键未知、方法可行且结果支持值得继续时，才扩大规模。项目已获得足以支撑当前决定的证据时停止，不为达到“40–60%”或看起来完整继续堆工作。

## 文献与成熟方法

优先复用成熟工具、统计方法、分组思路、对照、平台 SOP 和证据升级路径。论文只作为 METHOD_REFERENCE、DISCOVERY_PATH_REFERENCE 或已知边界；具体候选、预期方向和故事仍由当前项目证据产生。

来自当前数据、技术可信且多证据支持的新信号，不因缺少高水平先例而自动降级。自己的可靠结果与论文相反时，不修剪到先例方向。

## 输出合同

1. 当前决策问题；
2. 项目内候选来源和证据边界；
3. 最低充分模型、组别和干预；
4. 实验单位、重复、样本量依据和主要终点；
5. 必要对照与质量观察；
6. 支持、部分支持、相反、无差异和实验失效分支；
7. 样本与数据生命周期；
8. 结果属性（探索性 pilot / 确认性验证）及其升级条件；
9. 扩大、停止、换模型或降低 claim 的判据。

## 常见失败

- 固定要求表达、表型、机制、rescue 四步齐全；
- 所有组学都套每组 3 个或 2v2；
- 用前期完成百分比代替问题判断；
- 只做支持预期方向的读出；
- 还没验证核心观察就耗尽样本做大组学；
- 从论文复制候选或预期答案；
- 无论结果是什么都继续同一路线；
- 把技术失败写成候选不成立。
