# SCI 文献深度解读

按基础版「手把手文献带读」的方法，对有完整 work model 的研究论文做深度解读。核心是拆解文献的科研逻辑，不仅要看作者讲出来的，还要看作者没讲出来的，包括逻辑节点之间的真实关系、作者回避的漏洞、可以改进的地方。

解读视角是作为文献解读者去拆解文献，不被作者牵着走。作者写出来的逻辑要复述，作者没写出来的逻辑要主动推理，作者回避的问题要点出来。

产出形式是公众号推文（BioAdvance 风格），不是学术报告。以一个读完文章的同行或师兄分享怎么解读的口吻，问题驱动逐层剖析逻辑，自然融入方法论内核，不显式标章节步骤。人称用我/我们/师兄我 交替，不署名大师兄。

---

## 何时使用

- 用户上传 SCI 文献 PDF 或给 DOI，要求深度解读时
- 组会文献汇报准备，需要深入理解文章科研逻辑时
- 学习文章的课题设计思路，想借鉴到自己课题时
- 想看透一篇文章的 work model 和逻辑节点如何被实验证实时

不适用于，文献检索（用 literature-review）、文献综述写作（用 review-writing）、轻量框架解析（只看 Figure 小标题不深入结果细节）。

## 输入处理

### Step 1 接收输入

输入方式两种：
- PDF 文件上传（优先，能做完整深度解读）
- DOI 或 PubMed 链接（先尝试用 LiteratureSearch 或 WebFetch 获取全文）

### Step 2 全文检查与 PDF 解析

**优先用 MinerU 云端 API 解析 PDF**（不重复造轮子，MinerU 是 74k stars 的成熟开源 PDF 解析引擎，所有高质量文献解读工具底层都用它）：

- **flash-extract 模式**（免 Token、免 GPU）：单文件最大 10MB/20 页，输出 Markdown（公式和表格默认开启）。适合大多数 SCI 文献
- **精准模式**（免费申请 Token）：最大 200MB/200 页，支持批量，输出 Markdown/HTML/LaTeX/JSON。适合大文件或超 20 页的文献
- MinerU 一次性解决文本提取+图片提取+表格（转 HTML）+公式（转 LaTeX）+OCR（109 种语言，扫描版 PDF 也能处理）

**MinerU 不可用时的降级方案**：
- 文本版 PDF：pdftotext 提取文本 + PyMuPDF（fitz）提取图片
- 扫描版 PDF：pdftoppm 转 200dpi 图像 + tesseract OCR（chi_sim+eng 语言包）

**全文检查**：
- 如果只拿到 DOI/链接，先尝试获取全文。看不到全文时，先提醒用户「只拿到摘要，无法做深度解读，请上传 PDF」
- 全文获取后进入 Step 3

### Step 3 文献类型判断

解读前先判断文章是否有完整 work model（表型+机制+rescue 的因果逻辑）：

**有完整 work model 的研究论文**（CNS 主刊/大子刊/10+ 文章常见）→ 进入深度解读流程

判断标准：
- 有明确的表型发现（A-D 关系，实验证实的核心现象）
- 有机制研究（B-C 因果链）
- 有 rescue 实验证实因果关系（不是纯相关性）

**没有完整 work model 的文章**（纯表型/纯生信/综述/案例报告）→ 提示「这篇文章不适合深度解读，建议用框架解析」，并简单做框架解析：
- 思维导图罗列每个 Figure 小标题
- 找出每个小标题的主要实验及样本分组
- 分析小标题之间的逻辑关系并归类
- 判断创新性（表型创新还是机制创新，创新性够不够发这个杂志）

## 解读方法（四遍阅读 + 推文叙事）

借鉴 paper-explainer 的四遍阅读法建立理解，再用推文叙事输出解读。

### 四遍阅读（建立理解，不直接输出）

**第一遍 抓骨架**：读题目、摘要、引言、结论、章节标题、图表、公式、贡献声明。建立文章整体框架认知。

**第二遍 逐节精读**：按编号章节和重要子章节展开，记录每节的问题、概念、假设、证据、方法、失败案例、局限和前后文关系。

**第三遍 图表公式证据复核**：回看全部图、表、公式、实验结果和关键 claim，检查解释是否和原文一致。这一遍重点确认 work model 的每个逻辑节点是否有实验支撑。

**第四遍 读者断点补课**：专门找读者可能看不懂的内容（专业术语、实验技术、统计方法、模型选择理由），补背景桥接。这一遍同时找作者没讲出来的逻辑断点和回避的问题。

**深度参考**：四遍阅读法建立理解后，Introduction 切入方法、Results 逻辑递进读法、Discussion 长短处分析、Methods 模型设计读法这些精读细节，可以 load `literature-mining` skill 做交叉验证，确保精读定义和 meta-shixiong-research 系列一致。

### 推文叙事（输出解读）

四遍阅读建立理解后，用推文叙事输出解读。不显式标章节步骤，用同行分享的口吻自然展开。

#### 推文结构（思考骨架，不是固定的表层模板）

下面七个部分是推文的思考骨架，帮你想清楚一篇解读该有的层次。但它不是固定的表层模板，不要每篇都用同一套小节标题、同一个开头切入方式、同一个收尾。表层的措辞、节奏、切入点要因文而异，每篇读起来像独立写的。骨架在心里，不喊在标题上。

**1 标题**

有观点有态度，吸引点击，钩子以方法学为主。不写「文献深度解读」这种学术报告标题。三条原则：

- **句式要错开，不要每篇都用反问句**。反问句本身是一种套路，每篇都问「为何能上 Nature」就成了模板。判断式（这篇用一套双轴设计把两件事分开了）、反常识问句（肥胖明明促癌，为什么用了 PD-1 抗体反而应答更好）、方法陈述式（坐实一条通路要几条 rescue，这篇做了四条加双向验证）都可以，多篇之间要用不同句式，一批稿子里问号别扎堆。
- **钩读者认得出的共性痛点或方法问题**，不要在标题里点具体角色。「这篇怎么把 cross-dressing 和 cross-presentation 分开」这种点了具体分子的标题，读者没做这个课题就没共鸣；换成读者从自己课题也会遇到的方法问题（比如一个配对模型怎么控住混杂、坐实一条通路要几条 rescue），钩子才广。具体的分子和角色留正文揭。
- **标题不要提前点破批评**。这是学习式解读，标题给的是方法学钩子，不是「这篇有什么硬伤」。把结论和质疑放在标题里会让整篇基调变成挑刺，也剧透了正文。

好标题的例子（句式各不相同，都不剧透、都钩共性）：
- 判断式：「这篇 Nature 用一套双轴设计，把单核细胞的抗原递呈和 cDC1 干净地分开了」
- 反常识问句：「肥胖明明促癌，为什么用了 PD-1 抗体反而应答更好」
- 方法陈述式：「坐实一条代谢免疫通路要几条 rescue，这篇 Nature Cancer 一口气做了四条加正反双向验证」

坏标题的例子：
- 「文献1深度解读：癌细胞劫持单核细胞逃逸免疫」（学术报告标题，没观点）
- 「Nature 2024 文献解读」（太平淡）
- 「这篇的 rescue 设计为何能上 Nature？」（多篇都套这个反问句式就成了模板）
- 「这篇为何只能发 10 分上不了大子刊？」（标题提前点破批评，把学习式解读变成了挑刺）

**2 开篇切入**

以问题或判断切入，直接抛出这篇文章最值得剖析的核心增量。不罗列基本信息（发表时间、杂志、影响因子这些放后面自然带出或放文末）。

开篇要回答一个问题：这篇文献最值得读者看的是什么？是 rescue 设计巧妙？是 work model 拆解清晰？是 story 重构高明？还是作者回避了什么关键问题？

**3 模式图加 work model**

先看模式图，用 A-B-C-D 模型拆解 work model。自然带出，不显式标「work model 拆解」作为章节标题。

A-B-C-D 模型定义（来自 hypothesis-construction skill 的成熟框架）：
- A 是起点（基因/药物/因子/细胞群）
- D 是终点（疾病/表型）
- A-D 构成表型（一个现象，「知其然的然」）
- B-C 是中间环节，构成机制（解释现象的因果链，「知其所以然的所以然」）

拆解 work model 时把 A 起点、D 终点、中间 B-C 机制讲清楚即可，怎么引出因人而异。可以先讲问题和冲突再自然引到模式图，也可以边分析边呈现，不必每篇都用「先看这篇文章的模式图」当第一个小节。

从 PDF 提取 work model 模式图嵌入。如果文章没有模式图，用文字加箭头图示自己画因果链，A → B → C → D。

**4 逐层剖析逻辑**

按文章逻辑递进，逐层拆解。每个关键逻辑节点用问题驱动：
- 「为何要做这个实验？」（上一个结果推出什么，导致要做这个）
- 「这个结果推出什么？」（如何推进 work model 论证）
- 「作者这里有没有回避什么？」（替代解释、实验设计漏洞、强行串联的痕迹）

在剖析过程中自然融入方法论内核，不显式标章节：

**柯霍氏法则评估因果论证**（来自 causality-rescue skill）：在评估某个逻辑节点的因果论证强度时自然用，说「相关性做了」「敲除减弱做了」「rescue 回补做了吗」，但不显式标「分子柯霍氏法则三步评估」。

分子柯霍氏法则三步：
1. 相关性：A 与表型 D 相关
2. 去除减弱：敲除/抑制 A，表型 D 减弱
3. 回补恢复：过表达/回补 A，表型 D 恢复（rescue 实验）

一篇没有 rescue 实验设计的文章，基本不可能上一区或 10+。哪些逻辑节点没做 rescue，就是断点。

**6 Figure 骨架判断逻辑完整性**（来自 sci-writing-and-revision skill）：在判断文章 Figure 逻辑完整性时自然用，说「这篇 Figure 1 是临床数据，Figure 2 是体外表型，Figure 3 是体内...」，但不显式标「6 Figure 骨架判断」。

6 Figure 骨架（CNS 文章常见结构）：
- Figure 1：临床/公共数据提示 A 与疾病相关（表型线索）
- Figure 2：体外证实 A 对 D 的表型作用
- Figure 3：体内证实 A 对 D 的表型作用
- Figure 4：A 调控 B 的第一层机制
- Figure 5：B 调控 C 影响 D 的第二层机制加 rescue
- Figure 6：临床样本验证或讨论延伸

哪些 Figure 缺失，逻辑链就断在哪里。

**story 重构分析写作顺序**（来自 sci-writing-and-revision skill）：在分析作者写作顺序时自然用，说「作者实际研究顺序可能是从单基因出发，写作时重构为从临床问题出发」，但不显式标「story1 vs story2 对比」。

- story1（单基因出发）：实际研究常从单基因出发
- story2（临床问题出发）：写作时常重构为从临床问题出发

分析作者为什么选择这种写作顺序（彰显意义/制造悬念/规避弱点）。

**5 看作者没讲出来的**

在剖析过程中主动推理，点出：
- 这个结果有没有其他解释（作者是否回避了替代解释）
- 实验设计有没有漏洞（对照组够不够、样本量够不够、模型选择合不合理）
- 逻辑过渡是否自然（有没有强行串联的痕迹）
- 哪些逻辑节点其实没有实验支撑（只是推理）
- 真实研究顺序可能是什么（从哪个结果开始的）
- story 重构有没有掩盖研究弱点

这是这个 skill 的核心价值，也是和普通文献解读的区别。不被作者牵着走，主动推理作者没讲出来的。

**「不被作者牵着走」的三层深度（自检的标尺，不是逐条打卡的模板）**

「看作者没讲出来的」有三个递进的深度，越往后越见功力。

第一层，识破写作叙事的包装。看出 research story 是重构过的，写作顺序不等于真实研究顺序，作者从临床问题倒着讲往往是为了彰显意义。

第二层，看作者主动承认的局限并往前推一步。作者在 Discussion 里写的「本研究未做 X」不能只复述，要追问这个缺口对结论或转化到底有何影响。

第三层，看作者回避的、或压根没意识到的证据缺口和替代解释。比如关键实验的对照分不干净、结果存在另一种解释、核心结论和领域主流共识有张力而作者淡化了、临床证据本是相关性却被叙事包装成因果。

判断基准是这样的。如果这一节只停在复述作者自己承认的局限（第一、二层），说明还没真正独立，这一节就不够硬。至少要够到第三层里的一两个点，才配得上「不被作者牵着走」。这三层是自检的标尺，够到第三层的深度即可，不必凑满形式、也不必每层都写。

**批评的比重，收尾留质疑，中间改中性。** 学习式深度解读的主体是欣赏作者做对了什么、哪些做法能迁移到自己课题，不是通篇挑刺。大师兄专业版不可能从头批到尾。落到具体分寸：正文中段遇到可以质疑的地方（对照、scope、模型工具的局限），不要写成挑刺，改成中性的方法心得，说清楚这个设计证到了哪一层、边界在哪、读者自己做类似实验时该先想清楚什么，并且点明这不是这篇的短板；把真正的独立质疑收到每篇结尾点到一处，一个提醒加一个开放问题即可，而且这一处要够到上面说的第三层。这样整篇读起来是同侪在分享一篇好文章值得学的地方，末尾留一个值得继续想的问题，而不是一份挑毛病清单。标题同理，不提前点破批评（见前面标题那节）。

**6 提炼可迁移的方法**

让读者读完能学到能用的东西，比如组学数据里确定候选基因常用的两种思路、rescue 设计的几条验证线、配对模型为什么是逻辑地基。

这些可迁移的方法自然融进叙述即可，该点透的地方点透，不必每张图后面都硬跟一句「做课题时怎样怎样」。可以在剖析过程中随手带出，也可以在结尾附近收拢一下，形式不固定。要具体、可操作，不是空话。

**7 结尾**

轻量收束，不用固定话术。可以留一个开放问题给读者，也可以用一句自然的话把这篇的启发收束好。每篇结尾各写各的，不要一字不差地重复「欢迎点赞、关注支持大师兄」这类公众号套话。

#### 方法论内核的融入原则

A-B-C-D 模型、柯霍氏法则、6 Figure 骨架、story 重构这些方法论内核是这个 skill 的核心价值，但要降低反复提及的比例，融入推文叙事自然带出，不显式标章节步骤。

就像降低金句比例一样，尽可能还原自然的写作原貌。读者读到的是一篇流畅的推文，不是一份方法论清单。方法论内核在需要的时候自然出现，用完就回到推文叙事，不反复强调「这是 A-B-C-D 模型」「这是柯霍氏法则」。

**深度参考**：上面内联的方法论内核够大多数情况用。遇到复杂情况（多基因协同、A 或 D 难以定位、表型和机制边界模糊、需要判断 work model 是否成立、需要深度判断 rescue 设计是否严谨、需要判断 Figure 逻辑完整性、需要借鉴文章写作思路到自己论文）时，load 对应的 skill 拿完整方法：
- `hypothesis-construction`：work model 搭建方法和判断标准
- `causality-rescue`：因果论证方法和 rescue 设计标准
- `sci-writing-and-revision`：Figure 逻辑框架和 story 重构方法

## 解读视角

作为文献解读者去拆解文献，不被作者牵着走。这是这个 skill 的核心原则。

- 作者写出来的逻辑要复述
- 作者没写出来的逻辑要主动推理（逻辑节点之间的真实关系、作者回避的漏洞、可以改进的地方）
- 不只看文章讲了什么，还要看文章为什么这么讲、回避了什么、能不能做得更好

要警惕一个常见的伪独立，把作者在 Discussion 里自己承认的局限重新讲一遍，这不是「看作者没讲出来的」，这是复述作者的自我批评。真正的独立是够到上面推文叙事里说的第三层，看出作者回避或没意识到的证据缺口和替代解释。

## 表达规则

### 不能看不懂检查

读者可能卡住的内容必须补「背景桥接加直觉解释加技术解释加忽略会怎样」四层解释。包括：
- 专业术语（如「work model 就是文章最终证实的科学假设，体现 A-B-C 因果逻辑结构」）
- 实验技术（如「CO-IP 是免疫共沉淀，用来找蛋白和蛋白是不是直接结合」）
- 统计方法（如「log-rank test 是比较两组生存曲线有没有差异的检验」）
- 模型选择理由（如「为什么用 NSCLC 而不是其他癌症，因为该课题组前期数据在这个癌种」）

### 英文词汇护栏

默认不假设读者熟悉学术英语。关键英文词和不常见普通词必须给出「中文直译加本文语境」，例如：
- `retrieval（检索；本文语境：从记忆库或向量库中找回相关内容）`
- `phagocytosis（吞噬作用；本文语境：巨噬细胞吞噬肿瘤细胞碎片的过程）`
- `rescue（回补恢复；本文语境：敲除某个基因后表型消失，再把这个基因加回去表型恢复，证明因果关系）`

### 图表处理规则

| 原论文对象 | 处理方式 |

| work model 模式图、机制示意图 | 从 PDF 提取源图嵌入，如果源图是英文可考虑用文字加箭头图示自己画中文版因果链 |

## 输出格式

### 推文结构（markdown，图文混排）

推文模板见 references/report_template.md。模板是思考骨架，不是固定表层结构，表层措辞和切入方式因文而异。

思考骨架（不喊在标题上）：
1. 标题（提问式/判断式，有观点有态度，每篇措辞不同）
2. 开篇切入（以问题或冲突切入，抛出核心增量，每篇切入点不同）
3. 模式图加 work model（A-B-C-D 模型自然带出，引出方式因文而异）
4. 逐层剖析逻辑（问题驱动，自然融入柯霍氏法则/6 Figure 骨架/story 重构）
5. 看作者没讲出来的（够到第三层的独立质疑，不只复述作者承认的局限）
6. 提炼可迁移的方法（自然融入，不每图硬跟一句）
7. 结尾（轻量收束，各篇不同，不用固定话术）

### 图片嵌入

- work model 模式图：从 PDF 提取，嵌入推文对应位置
- 各 Figure 代表图：从 PDF 提取关键 Figure 的主图，嵌入对应剖析段落
- 图片提取用 MinerU（优先）或 PyMuPDF（fitz）
- 图片保存到 `/mnt/results/literature_reading/images/`，推文用相对路径引用
- 交付前图片自检：检查所有图片完整嵌入，路径正确

### 字数

参考 3000-4000 字（中文字加英文词加数字），不作为硬性限制。内容需要多少就写多少，核心是保证推文感和深度。聚焦核心增量，不追求逐 Figure 罗列。

### 推文保存

- 保存到 `/mnt/results/literature_reading/[文章简称]_解读推文.md`
- 文章简称用通讯作者加主要表型（如 `TREM2_mo-macs_NK_解读推文.md`）

## 语言风格

产出是推文不是学术报告。底子是一个读完这篇文章的同行或师兄在跟你分享他怎么解读的，有观点、有态度、亲切，但沉稳。

- 解读主体是「我」，人称不锁死，我 / 我们 / 师兄我 按语境交替出现，不要固定一种、也不要在同一篇里机械轮换。不署名「大师兄」，落点是解读者本人。
- 有判断有态度，不被作者牵着走。看作者讲出来的，也看作者没讲出来的。
- 沉稳但不失亲切，像学术同侪或前辈分享经验。不堆砌重复冗余的话，不用生硬的 AI 式表达（「值得注意的是」「总而言之」「综上所述」这类套话按需削减）。
- 零认知摩擦，陌生术语首次出现要解释。
- 标题有观点、判断式或提问式。开篇以问题或冲突切入，不罗列基本信息。
- 标点规则，全程无双引号（用「」），无破折号，尽量不用冒号。
- 结尾轻量收束，不用固定的公众号互动话术。

**词汇 register 自查**。每一个字、词、句子在写出来之前，都要过一遍是否符合中文互联网学术科普的表达习惯，既不要过于口语随意，也不要过于生硬官方。落到具体的词上：

- 避开过口语的单字动词和俚俗说法，换成书面但不生硬的同义词。比如「拆」换成「拆解、分析」，「顶上去」换成「升高、被诱导上调」，「撞见」换成「发现、观察到」，「摁住、按住」换成「控制住、锁定」，「掰扯、掰开」换成「区分、辨析」，「凑一个结尾」换成「补一个结尾」，「收住」换成「收束、收尾」。也避开一批看着像口语实则不规范的说法，「软处、软肋」换成「薄弱环节、站不住的地方」，「没证到」换成「没有验证、缺少直接证据」，「顺完」换成「读完、梳理完、顺着看完」。
- 也避开另一个极端，不要为了书面就堆学术八股。像「本文旨在」「综上所述」「不难看出」这类论文腔同样要避开。目标是一个懂行的同行在自然、清楚地讲，不是宣读报告。
- 一个简单的判断办法，把写好的句子想象成发在一条面向研究生的科普推送里，读起来是否自然、是否有哪个词显得随意或做作。有，就换掉。

**句式与节奏自查**。词换干净之后，还有更隐蔽的一层，是句式结构。AI 腔在句式层最容易露馅的根因只有一个，把每个信息单元都收进一个工整、可预测的外壳，读者读几段就能预感到下一句的形状。要避开的是这种可预测的整齐，不是某几个具体句式，所以下面不列禁用清单，只点三个高发位置，各给一组改前改后。

- 段落起手别复用同一批词。反例，连续几段都用「先…／接着…／然后…」开头，读着像流程说明书。正例，让每段从自己的内容切入，有的从一个疑问起，有的直接抛结论，有的承接上一段落脚的那个具体名词往下接，起手参差着来。
- 方法心得的收尾别都归到同一个对比句式。反例，几处心得都用「…往往更靠谱」「说服力会明显不一样」「就比…强得多」这类对比句收口，三段连读像一个模具压出来的。正例，有的用陈述句平收，有的把心得直接长在对实验的评述里、不单独总结，有的换一个落点，不都落在「更…／得多」这种比较级上。
- 心得的引出别都用同一个转场。反例，多处用「自己做课题时…」「自己面对…时…」把心得推给读者，成了可预测的套路。正例，让心得自然长在正文的评述里，或换不同说法带出，不固定一个转场词。

一个自查办法，写完把连续几段的起手词拉齐看一遍，再把每段的收尾句拉齐看一遍。如果起手词雷同、或者收尾都落在同一个对比句式上，就打散。判断标准还是那句话，读者会不会预感到下一句的形状，会，就换。

## 质量控制

解读推文交付前做三轮质检：

**Coverage reviewer（覆盖检查）**：
- 核心逻辑节点是否覆盖
- 关键 claim 是否都有分析
- 不要求每个 Figure 都解读，聚焦核心增量

**Technical reviewer（技术准确性）**：
- work model 拆解是否准确
- 因果论证评估是否正确
- 术语解释是否准确

**Readability reviewer（可读性）**：
- 推文风格是否到位（标题有观点、开篇问题切入、结尾轻量收束）
- 标题是否过关（有方法学钩子、钩共性痛点不点具体角色、句式因文而异不套固定反问句、不提前点破批评）
- 批评比重是否过关（主体是欣赏和可迁移方法，中段可质疑处改成中性方法心得并点明不是短板，独立质疑只在结尾点到一处且够到第三层，不是通篇挑刺）
- 去模板化是否到位（三篇小节标题不共用一套措辞、开头切入点不同、结尾不同、可迁移方法不每图硬跟一句）
- 人称是否自然（我/我们/师兄我 交替，不锁死、不机械轮换，不署名大师兄）
- 语言是否沉稳不失亲切（不堆砌重复冗余的话、无生硬 AI 套话、无双引号无破折号尽量不用冒号）
- 词汇 register 是否过关（无过口语的单字动词和俚俗说法，如 拆/顶上去/撞见/摁住/掰扯；也无论文八股腔；每个词都符合中文互联网学术科普的表达习惯）
- 不能看不懂检查是否到位，英文词汇护栏是否执行
- 「看作者没讲出来的」是否够到第三层（有作者没主动承认的独立质疑，不只复述 Discussion 里的局限）
- 方法论内核是否自然融入（不显式标章节步骤）

严重度分级（P0-P3）：
- P0 致命：work model 拆解错误、严重编造
- P1 严重：逻辑节点分析错误、关键 claim 漏分析、图表缺失
- P2 中等：术语解释缺失、英文词汇护栏未执行、推文风格不到位、词汇 register 不符（过口语的单字动词或俚俗表达，或反过来论文八股腔）、方法论内核显式标章节步骤、多篇共用固定表层模板（同套小节标题/同套开头/同套结尾）、「看作者没讲出来的」只停在复述作者承认的局限（没够到第三层）、标题套固定反问句式或提前点破批评、批评比重失衡（中段把可质疑处写成挑刺而非中性方法心得，或质疑铺满全篇而非收到结尾一处）
- P3 轻微：表达不顺、过度压缩

交付前必须修复所有 P0-P2。
