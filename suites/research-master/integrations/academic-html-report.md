# Academic HTML Report 接入合同

## 入口

`academic-html-report` 是相邻输出系统，不计入 18 个大师兄逻辑模块。按当前全局规则，只有用户明确要求学术 HTML 报告或大型结构化 HTML 交付物时才调用；普通科研分析、单图检查、参数查询和日常对话不自动触发。

## 内容权力

- 科学问题、主线、结论和证据等级来自对应科研 skill、真实数据和已确认项目状态。
- 复杂科研 HTML 开写前必须取得相关方法论 skill 的 `methodology_projection`，并通过 `render_report.py --research-state` 传入报告渲染链。渲染器会校验方法判断、把状态嵌入 HTML 并写入 manifest；问题树、证据顺序、Figure 顺序和下一步都要承接这些决定。只有通用表达核、没有方法论投影时，不得直接生成复杂科研叙事。
- HTML skill 可以自由决定章节、导航、图组和表格布局，但不能固定套七区、控制台或仪表盘。
- 展示顺序优先图片证据，其次表格，再次普通文字；展示优先级不能升级科学证据强度。
- 每个主要证据块先给发现和判断，再给最高价值的下一步。证据边界只在会改变结论或行动的位置出现一次，不把“不能证明什么”做成每图必填项。
- 成稿在同一次语言收口中使用 `anti-defensive-writing` 和 `avoid-ai-writing`；直接修正文，不新增审计附录、模型调用或确认环节。
- 成稿同时执行 `shared/expression-core.md` 指向的统一大师兄禁用词检查。硬禁命中必须改完并重检，软提醒只在形成模板腔时处理。

## 图片与单文件交付

- 当前报告涉及的所有正式图片必须真正嵌入 HTML。
- PNG/JPEG 使用 data URI；SVG 内联或 data URI；PDF 渲染为可读预览后嵌入。
- 证据图是不可改写的原始证据。原图是英文就保留英文；中文要求只约束 HTML 标题、正文、图注、表头和交互文字。
- 不得为了统一语言或美化页面而翻译、重画、改标签、改颜色、裁掉信息或覆盖原图。PDF 转成浏览器预览图时只允许整页等比例渲染，内容、比例和版式保持不变。
- 用户明确要求制作新图时，才另行生成新版本；原图仍须单独保留并绑定哈希，不能被新图替换。
- 不得依赖服务器绝对路径、临时 URL 或旁置图片目录才能显示。
- manifest 分别绑定原始证据文件和浏览器预览图：两者都保留报告内副本、字节数和哈希，PDF/SVG 原件与 PNG 预览不能互相冒充。
- 交付前必须在真实浏览器打开并复核图片、表格、字号、截断、布局和可读性。

## 视觉基线

极简、干净、有辨识度；允许协调的多色体系，但不能刺眼。字体较大、版心舒展、留白充足，图表优先获得展示空间。视觉服从证据链，不反过来固定报告结构。

## 当前状态

本合同已接入正式 `academic-html-report`：复杂报告必须绑定上游方法判断，manifest 记录方法判断源文件及哈希；自包含图片、原始证据/预览双哈希和真实浏览器渲染继续按原合同验收。
